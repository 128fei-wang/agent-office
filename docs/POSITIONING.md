# Positioning

> 状态：Phase 0 产出（v1.28.0 之后的方向校准）
> 一句话：**给已经在用 Claude Code / Codex 的个人和 2–10 人小队，一个本地优先、MCP 原生、每个任务都有真实证据和审批记录的控制台；办公室是它的实时观察窗口。**

## 1. 我们不是什么

- 不是又一个「AI 编码 Agent」：执行交给用户已经付费的 Claude Code、Codex、OpenCode、Aider 等 CLI。
- 不是云端多租户平台：默认 loopback、本地存储、零依赖；隐私是卖点，不是妥协。
- 不是办公室游戏：像素办公室是观察层和传播资产，不是产品核心。

## 2. 我们要解决的真实问题

一个人或小队同时跑多个 Agent 时，真正难的不是"让 Agent 写代码"，而是：

1. **任务从哪来、归谁、到哪一步了**——看板 + 依赖 + 认领/完成语义。
2. **它到底改了什么、测过没有**——真实 worktree/diff/测试输出，而不是模型自述。
3. **我什么时候该介入**——花费、拍板、登录、授权四类审批门；其余技术问题由团队自己解决。
4. **出了事能不能追溯**——谁在哪个环境、用哪个 Agent、基于哪次审批、产出了什么 hash。

这就是「可审计的 Agent 控制台」（control plane），而不是「更聪明的 Agent」。

## 3. 核心循环（产品必须端到端打通）

```
Mission（老板写目标）
  → 拆解任务 / 推荐团队 / 分配
  → 每个任务一个 git worktree + 分支
  → 启动用户自己的 Agent CLI（PTY，实时日志）
  → 采集真实 diff + 测试输出 + 变更文件 hash
  → 交付验证（沙箱测试 / 路径策略 / 占位内容拒绝）
  → 老板审批（看 diff + 证据 + 风险）
  → merge / PR（或打回重做）
  → 审计导出（签名证据链）
```

## 4. 目标用户

- 已经在为 Claude Code / Codex 付费、每天开多个终端窗口的个人开发者。
- 2–10 人小队：需要审批、审计、可回滚，但不想上 SaaS。
- 想把"多 Agent 协作"讲清楚、演示给客户/老板看的人（办公室视图负责这件事）。

## 5. 差异化（按重要性排序）

1. **真实证据**：diff hash + 测试输出 hash + 策略偏差，签名、可导出、可离线验证。
2. **审批绑定真实动作**：审批的是具体 diff/命令/花费，而不是一段模型自述。
3. **策略/权限**：每个任务声明 Agent 可碰的路径、命令、网络、时长；越界即失败并留痕。
4. **MCP 原生**：Claude Code / Codex / Cursor 通过 MCP 领取任务、提交证据、请求审批。
5. **本地优先 + 零依赖**：一个 Python 进程 + 一个静态前端；无 Docker 也能跑。
6. **办公室观察窗口**：把并发、等待、审批、失败变成一眼能看懂的画面。

## 6. 非目标（Phase 0 起不再投入）

- 一人公司模板、演示 Agent、模拟 Trace 遥测作为主卖点。
- 无签名的自动更新。
- 自建 Agent 运行时/容器平台（执行交给现有 CLI）。
- 追 10+ Agent 适配数量；先把 Claude Code + Codex 做到可靠。

## 7. 90 天路线

| 阶段 | 时间 | 产出 |
| --- | --- | --- |
| Phase 0 止血 | 1–2 周 | 状态损坏保护、审批不过验证不置 done、manual 更新本地化、provider baseUrl 变更确认；本文件 |
| Phase 1 真实执行 MVP | 3–4 周 | runner（worktree + PTY + diff + 测试）、任务/运行/证据 schema、run API + SSE、MCP 工具、UI 任务抽屉 |
| Phase 2 治理差异化 | 4–6 周 | 策略引擎、独立验证者、签名证据导出、增量 API/队列/检查点、SQLite |
| Phase 3 分发与商业 | 持续 | 一键安装、无 bridge 演示、GitHub App PR、公开只读看板、开源核心 + 团队版 |

## 8. 成功指标（90 天）

- 首次任务 < 5 分钟；每个任务都有真实 diff + 测试证据。
- 审批 → 合并成功率 ≥ 90%；审计导出完整性 100%。
- 周活任务数、崩溃/假红率、星标/issue 转化率。
